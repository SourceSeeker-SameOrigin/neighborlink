# 近邻帮 UI 实施基准（D43，用户已批准）

唯一视觉基准：[用户认可的三屏设计稿](approved-ui.png)。用户再次明确所有页面必须严格沿用该风格。下面是实现与验收约束，不是另提一套设计。

| 维度 | 要求 |
|---|---|
| What 做什么 | 69 页全部统一；首页、门牌、我的对照原图；其他页面使用同一套标题、菜单、表单、卡片、主次按钮及空状态 |
| Why 为什么 | 修正此前“只统一色彩/卡片”与批准稿在结构、比例、插画、入口呈现上的差异 |
| Who 谁负责 | 开发者逐页实施与技术核查，用户按实际运行界面验收；不能由开发者宣布主观视觉已被用户接受 |
| When 何时 | 基准三页 → 共用组件 → 业务与工作台页面 → 全量编译/事件核对 → 实际截图与流程验收 |
| Where 在哪里 | 微信原生小程序；住户、服务员、商家、驿站、管理员/物业；不得另换 UI 框架 |
| How 如何验收 | 核对布局/字号/配色/图标/插画/留白/按钮；长文本和窄屏无重叠；业务字段、路由、事件及权限不丢失；源码覆盖不代替真机验收 |
| How much 多少 | 69 页、8 个公共组件、两幅正式插画与本地图标；没有购买 UI 服务。真机逐页耗时取决于账号及数据前置，尚未估定 |

## 必须保持的视觉结构

- 首页：位置及登录状态 → 浅绿插画横幅 → 四项核心服务两列卡 → 暖杏色月卡条 → 完整服务目录（状态说明/可用直达）；标题旁细绿竖线，图标采用深绿线条与暖黄/浅绿填色。
- 选择门牌：建筑/树木横幅 → 两步骤提示 → 小区、楼栋/单元、房号白色行式表单 → 可展开联系人 → 电话卡 → 协议 → 保存及返回。D44 将参考稿的授权按钮改为手填输入及“未验证”说明，这是用户明确批准的功能差异。
- 我的：通用插画头像及登录标签 → 资料卡 → 两列服务菜单 → 邻居帮手图文入口 → 协议列表 → 细线页脚。统一显示工作台资格；有角色可进入，无角色显示申请/审核说明。
- 其他页：同一浅绿图标标题区，白底表单/详情卡、细分隔线、圆角菜单、深绿主按钮/描边次按钮。后台统计、审核、任务、聊天仍保留各自业务结构，不变成首页宫格。
- 正文至少 32rpx，可点击操作至少 88rpx。参考图片不是某个真机的像素尺寸；较窄或较矮设备允许自然换行/纵向滚动，禁止为一屏塞满而压缩正文。
- 危险、失败、未验证状态使用明确文字，不仅依赖颜色。禁用按钮不伪装成功；功能开关关闭不凭样式开放业务。

## 色彩和资产

`design-tokens.json` 记录基础色。实际样式以 app.wxss 和公共组件为入口，页面只写业务布局；禁止再次散落旧的默认灰框/红色主按钮等不一致样式。

- `approved-ui.png`：批准稿，保留原样。
- `neighborhood-approved-style.png` 与 `address-neighborhood-original.png`：根据批准稿提取风格重建的插画源图；在小程序中使用缩小后的透明 PNG。它们属于生产插画资产，不是新增设计方案或实际运行截图。
- `scripts/generate-ui-icons.py`：项目内可编辑的原创图标源；输出深绿线条图标和三个独立 tab 图标。
- `docs/verification/2026-11-08-ui/*-native.png`：实际开发工具截图。视觉核查与用户验收状态分别记录，不能混用生成图。

## 全量验收

见 [69 页清单](../verification/2026-11-08-ui/page-coverage.md)。没有对应业务角色/记录的页面保留“待实景验收”，不伪造云端账号或已付订单。主包必须小于 2MB；最终以开发工具当前统计为准。
